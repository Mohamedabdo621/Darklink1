# DARKLINK — تطبيق تواصل اجتماعي (هوية مجهولة / عامة)

تطبيق اجتماعي فاخر داكن (Dark Premium × Neon Purple) بهوية يختارها المستخدم:
مجهول باسم مستعار ثابت، أو عام باسمه — مع محادثات ورسائل صوتية وهدايا ومحفظة جواهر.

## البنية

- **Frontend:** React Native + Expo SDK 58 + TypeScript + Expo Router — `app/`
- **Backend:** Supabase (Auth + PostgreSQL + RLS + Realtime + Storage)
  - المخطط: `supabase/migrations/0001_darklink_schema.sql`
  - بيانات أولية (باقات + هدايا): `supabase/migrations/0002_seed.sql`
  - دالة حذف الحساب: `supabase/functions/delete-account/`
- **التصميم المرجعي:** `docs/design-reference.jpg` — صور الهدايا داخل `app/assets/gifts/`

## قواعد الأمان المنفذة في المخطط

- العملاء لا يقرأون `profiles` لغيرهم أبدًا — الاكتشاف عبر View آمنة
  (`discover_profiles`) تعرض الاسم المستعار/المعروض فقط، والبريد لا يغادر المالك.
- المحفظة: لا كتابة من العميل إطلاقًا؛ الشراء والإهداء عبر دوال
  `SECURITY DEFINER` ذرية (`purchase_gems`, `send_gift`) مع منع التكرار
  والرصيد السالب والحظر المتبادل.
- وسائط المحادثات والصوتيات في Buckets خاصة بمسارات
  `{conversation_id}/{sender_id}/...` وسياسات وصول للأطراف فقط.
- الدفع: `app_config.billing_mode = 'sandbox'` حاليًا — لا جواهر تُضاف في
  وضع الإنتاج إلا بعد تحقق خادمي من إيصال Google Play.

## التشغيل عند النشر

1. إنشاء مشروع Supabase وتشغيل الـ migrations بالترتيب.
2. تفعيل تأكيد البريد في Auth — التأكيد بلينك في الإيميل يفتح التطبيق
   (الخطة المجانية لا تسمح بتعديل قالب الإيميل لكود 6 أرقام).
3. نشر دالة `delete-account`.
4. ضبط `EXPO_PUBLIC_SUPABASE_URL` و`EXPO_PUBLIC_SUPABASE_ANON_KEY` في بيئة
   التطبيق (انظر `app/.env.example`) — مفتاح anon العام فقط.
